“Save as draft” — but where does the draft live?

Three answers, and they are not cosmetic: each one decides what an unfinished job is to the rest of the app. This is the question I need answered before I build it.

What makes this sharp: allocateIntWo consumes a counter — the project's intWoCounter or the global yearly one. A number handed to a draft that is then abandoned is gone, and the sequence on client paperwork has a hole in it. Job.intWoId is also NOT NULL and unique today.
A
A real Job, numbered
Row created on first keystroke, lifecycle DRAFT
+Simplest to build. The row already exists, so every later edit is the edit path that already works.
+The draft is visible in Jobs, so somebody else can pick it up.
−Burns an INT WO number per abandoned draft. Open the page, change your mind, and 2607-P-9-0011 never exists.
−A job with no site and no company now flows through job lists, the dashboard, calendar sync, exports and payroll queries. Every one has to tolerate it.
−Somebody has to clean up the drafts nobody finished.
B
A real Job, unnumbered
DRAFT row now, number allocated on Create
+No gaps in the numbering — the counter is only touched by a job that becomes real.
+Still visible in Jobs, still handed over.
−Needs intWoId to become nullable — altering a NOT NULL column that carries a unique index, on a table with live data. The one migration shape I would rather not run a week after the last one.
−Same blast radius as A: half-filled jobs in every list and query.
~Everything that prints the INT WO now has to handle it being absent.
C — what I would build
Not a Job yet
A JobDraft row, per person; becomes a Job on Create
+Nothing can be lost — every keystroke is saved, which is the actual complaint.
+No number burned, no gaps, no migration on intWoId.
+Nothing half-made reaches job lists, the dashboard, calendars, exports or payroll. The blast radius is one new table.
+The validation bug stops mattering: a refused submit reloads from the draft instead of resetting.
~A draft is yours until you create it. If two planners should be able to share one, that is A or B, not this.
~One more table, and a rule for when an untouched draft is cleared.
